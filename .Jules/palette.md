## 2026-04-18 - Native disabled states for Streamlit forms
**Learning:** Streamlit forms and buttons often use a pattern of short-circuiting rendering (e.g., `if data and st.button(...)`) which hides the action entirely until valid data is provided. This is a UX anti-pattern because users don't know what actions are available or why they can't proceed.
**Action:** Always use the native `disabled` property on interactive elements (e.g., `st.button('Action', disabled=not data)`) combined with the `help` parameter to provide contextual tooltips explaining the required prerequisites.
## 2024-04-30 - Enhanced Asignación Masiva Form UX
**Learning:** When dealing with bulk-edit forms in Streamlit (like assigning a value to all visible rows), users often struggle to understand how to clear values vs set new ones, and the impact of the action button is not always immediately clear. Adding native `placeholder` and `help` parameters to input elements (`st.text_input`, `st.button`) provides immediate inline context without cluttering the UI with additional text blocks, and applying `use_container_width=True` to the action button improves alignment and prominence.
**Action:** Use native Streamlit tooltips (`help`) and placeholders to explain form behaviors, particularly for destructive or bulk actions, and ensure action buttons span the available column width for better visual hierarchy.
