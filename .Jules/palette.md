## 2024-05-24 - Dynamic Disabled States and Tooltips
**Learning:** In Streamlit, short-circuiting rendering (hiding buttons if data is missing) is an anti-pattern because users don't know the feature exists. Leaving them enabled when they will fail leads to bad UX. The best approach is rendering them unconditionally but using `disabled=not prerequisite_met` combined with the `help` parameter to explain exactly what data is missing to unlock the feature. This pattern also works well for potentially destructive actions, like mass assignment, by using `help` to clarify the consequences (e.g. leaving input empty will clear the data).
**Action:** Always check required data prerequisites (e.g., via `get_all_tables()`) before rendering action buttons, dynamically set the `disabled` state, and provide contextual guidance via `help` tooltips and input `placeholder`s.
